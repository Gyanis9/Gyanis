# 调度器接口

## 概述

`Scheduler` 是 `core` 模块中的协程任务调度器，负责在线程池中调度执行协程对象或普通回调。

本次重构目标：

- 使用 C++20 特性增强接口约束与可读性
- 日志输出以中文为主，方便定位调度行为
- 去除与 Unix 专属头文件的直接耦合，保证 Ubuntu 与 Windows 均可编译

头文件：`src/core/Scheduler.h`
实现文件：`src/core/Scheduler.cpp`

## C++20 重构点

1. `schedule` / `scheduleNoLock` 使用 C++20 `concept` 约束可调度类型。
2. 使用 `std::remove_cvref_t`、`std::invocable` 与完美转发，避免模板误用。
3. 统一使用现代标准库并发原语（`std::shared_mutex`、`std::scoped_lock`、`std::atomic`）。

## 主要接口

### Scheduler

- `Scheduler(size_t threadCount = 1, std::string name = "")`
- `void start()`：启动线程池
- `void stop()`：停止并回收线程
- `template<...> void schedule(FiberOrCb&& fc, int thread = -1)`：调度协程或回调
- `template<...> void schedule(InputIterator begin, InputIterator end)`：批量调度
- `void switchTo(int thread = -1)`：切换到指定线程执行
- `std::ostream& dump(std::ostream& os) const`：输出调度器状态
- `std::string toString() const`
- `static Scheduler* GetThis()`：获取当前线程绑定的调度器

### FiberSemaphore

- `bool tryWait()`：尝试获取信号量
- `void wait()`：等待信号量
- `void notify()`：释放信号量并唤醒等待任务
- `size_t getConcurrency() const`
- `void reset()`

### SchedulerSwitcher

- RAII 风格调度器切换器：构造时切换、析构时恢复。

## 日志约定

调度器日志统一使用中文前缀：`[调度器]`，包含如下场景：

- 启动/停止
- 唤醒信号
- 调度线程退出
- 非法切换请求（如当前线程无活跃协程时）

## 跨平台说明（Ubuntu / Windows）

- 不依赖 `Hook.h` 中的 Unix 专属 `unistd.h` 头文件。
- `FiberSemaphore` 的互斥锁类型采用 `std::mutex`，避免项目内已移除的自定义 `Spinlock` 依赖。
- 在 Ubuntu 与 Windows 均使用同一套标准 C++20 并发实现。
