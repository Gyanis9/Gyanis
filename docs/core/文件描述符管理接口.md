# 文件描述符管理接口

## 概述

`FdManager` 负责维护 `fd -> FdContext` 的上下文映射，用于记录文件描述符的运行时状态与超时配置。

- 头文件：`src/core/FdManager.h`
- 实现文件：`src/core/FdManager.cpp`

`FdContext` 主要保存以下状态：

- 是否已初始化
- 是否为 Socket
- 系统层非阻塞标记
- 用户层非阻塞标记
- 接收/发送超时时间

## C++20 重构点

1. 使用 C++20 安全整数比较（`std::cmp_less/std::cmp_greater_equal`）处理 `int` 与 `size_t` 比较，避免隐式转换风险。
2. 对关键查询接口添加 `[[nodiscard]]`，防止调用方忽略返回值。
3. 对容器扩容逻辑封装为独立计算函数，减少重复并提升可读性。

## 主要接口

### FdContext

- `explicit FdContext(int fd)`
- `[[nodiscard]] bool isInit() const`
- `[[nodiscard]] bool isSocket() const`
- `[[nodiscard]] bool isClose() const`
- `void setUserNonblock(bool value)`
- `[[nodiscard]] bool getUserNonblock() const`
- `void setSysNonblock(bool value)`
- `[[nodiscard]] bool getSysNonblock() const`
- `void setTimeout(int type, uint64_t value)`
- `[[nodiscard]] std::chrono::milliseconds getTimeout(int type) const`
- `[[nodiscard]] std::string toString() const`

### FdManager

- `[[nodiscard]] std::shared_ptr<FdContext> get(int fd, bool auto_create = false)`
- `void del(int fd)`

## 跨平台行为（Ubuntu / Windows）

### Ubuntu / Linux

- 使用 `fstat` 判断 `fd` 可用性与文件类型。
- 若为 Socket，尝试通过 `fcntl` 设置系统非阻塞。
- 保持与现有 Hook/网络逻辑一致的语义。

### Windows

- 采用安全回退策略，不对任意整数 `fd` 做 CRT 运行时探测，避免调试 CRT 的 invalid-parameter 中止。
- `FdContext` 仍可被创建并参与调度元数据管理。
- 超时选项常量在实现内提供兼容定义，保证跨平台编译一致性。
