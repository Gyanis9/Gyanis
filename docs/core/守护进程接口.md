# 守护进程接口

## 概述

`Daemon` 模块用于管理主进程启动方式：

- 前台模式：直接执行主回调。
- 守护模式：
  - Ubuntu/Linux 下采用 `daemon + fork + waitpid` 进行子进程守护与重启。
  - Windows 下采用兼容回退策略（记录进程信息并以前台方式运行主回调）。

文件位置：

- 头文件：`src/core/Daemon.h`
- 实现文件：`src/core/Daemon.cpp`

## C++20 重构点

1. 提供 C++20 约束的 `start_daemon` 回调重载（`std::invocable` + `std::convertible_to`）。
2. 使用更清晰的类型别名 `DaemonCallback` 降低接口噪声。
3. 保持接口可扩展，同时避免模板递归匹配问题。

## 主要接口

### ProcessInfo

用于记录守护运行状态：

- `parent_id`：父进程 ID
- `main_id`：主进程 ID
- `parent_start_time`：父进程启动时间
- `main_start_time`：主进程启动时间
- `restart_count`：重启次数

接口：

- `[[nodiscard]] std::string toString() const`

### start_daemon

- `[[nodiscard]] int start_daemon(int argc, char** argv, const DaemonCallback& main_cb, bool is_daemon)`
- C++20 模板重载：支持可调用对象直接传入。

返回值：

- 返回主回调返回值，或守护流程中的错误码。

## 跨平台行为说明

### Ubuntu / Linux

- 守护模式下调用 `daemon(1, 0)`。
- 父进程负责 `fork` 子进程并 `waitpid` 监控退出状态。
- 子进程异常退出时，按配置的 `daemon.restart_interval` 等待后重启。

### Windows

- 当前实现采用回退模式，不做 `daemon/fork/waitpid` 语义模拟。
- 当 `is_daemon=true` 时记录日志并以前台方式执行主回调，确保功能可用与编译稳定。

## 日志约定

日志以中文为主，前缀语义统一：

- 守护初始化失败
- 子进程启动/退出
- 子进程异常信号终止
- `waitpid`/`fork` 系统调用失败
- Windows 回退模式提示
