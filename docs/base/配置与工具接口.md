# 配置与工具接口

## 范围

本文档描述以下接口：

- src/base/Config.h

## Config 模块

### 1. ConfigVarBase

用途：

- 配置项抽象基类，统一配置项名称、描述、序列化与反序列化接口。

核心接口：

- getName()：返回配置项名称。
- getDescription()：返回配置项描述。
- toString()：将配置值序列化为字符串。
- fromString(value)：从字符串反序列化并更新配置值。
- getTypeName()：返回配置值类型名。

线程安全：

- 由派生类负责，基类不提供锁。

平台差异：

- 无平台差异。

### 2. LexicalCast

用途：

- 统一类型转换入口，支持基础类型与常见容器类型和 YAML 字符串互转。

支持类型：

- 基础类型：通过 boost::lexical_cast。
- 容器类型：
  - vector of T
  - list of T
  - set of T
  - unordered_set of T
  - map<string, T>
  - unordered_map<string, T>
- 业务类型：
  - LogDefine
  - TcpServerConf

线程安全：

- 转换器本身无共享状态，线程安全。

平台差异：

- 无平台差异。

### 3. ConfigVar 模板

用途：

- 保存单个配置项值，支持变更监听。

核心接口：

- getValue()：读取当前值。
- setValue(value)：设置新值，触发监听回调。
- toString()/fromString()：与字符串互转。
- addListener(callback)：注册变更回调。
- delListener(id)：删除单个回调。
- clearListeners()：清空全部回调。

返回语义：

- fromString(value)：
  - true：解析成功并已更新。
  - false：解析失败。

线程安全：

- 内部使用 shared_mutex。
- 读操作使用共享锁，写操作使用独占锁。
- 监听器 ID 使用原子计数生成。

平台差异：

- 无平台差异。

### 4. Config

用途：

- 全局配置注册中心，提供查找、加载、遍历。

核心接口：

- LookUp(name, default, description)：获取或创建配置项。
- LookUp(name)：按名称和类型查找。
- LookUpBase(name)：按名称查找基类指针。
- LoadFromYaml(root)：从 YAML 节点加载配置。
- LoadFromConfigDir(path, force)：从目录加载全部 yml 配置。
- Visit(visitor)：遍历全部配置项。

参数说明：

- name：配置名，仅允许 a-z、数字、下划线、点号。
- force：
  - false：文件未变化时跳过。
  - true：强制重新加载。

线程安全：

- 全局配置表由 shared_mutex 保护。
- 配置文件修改时间表由独立 shared_mutex 保护。

平台差异：

- 使用 std::filesystem，支持 Windows 与 Linux。

## Utils 模块

### 1. 通用函数

#### TypeToName 模板函数

用途：

- 返回可读类型名。

返回：

- string 类型的类型名文本。

平台差异：

- GNU 编译器族优先使用 demangle。
- 其他编译器返回 typeid 原始名称。

#### GetThreadID()

用途：

- 获取当前线程标识。

返回：

- uint32_t。

平台差异：

- Linux：优先使用 SYS_gettid。
- 其他平台：回退为 std::thread::id 哈希值。

#### captureBacktrace / backtraceToString

用途：

- 捕获调用栈并转换为字符串。

平台差异：

- Linux：使用 execinfo 进行符号化调用栈。
- Windows：降级返回提示文本，确保接口可用且可编译。

#### Time2Str / Str2Time

用途：

- 时间戳与字符串互转。

平台差异：

- 本地时间转换采用线程安全分支：
  - Windows：localtime_s
  - Linux：localtime_r
- Str2Time 使用 std::get_time，避免平台专属 strptime 依赖。

### 2. StringUtil

用途：

- 字符串格式化、URL 编解码、裁剪、宽窄字符串转换。

关键行为：

- UrlEncode 使用十六进制百分号编码。
- UrlDecode 支持加号与空格互转。
- Trim/TrimLeft/TrimRight 提供左右裁剪。

线程安全：

- 无共享状态，线程安全。

### 3. TypeUtil

用途：

- 字符串到数值类型安全转换。

关键行为：

- 转换失败返回 0 或 0.0。
- 失败原因写入中文日志。

线程安全：

- 无共享状态，线程安全。

### 4. FSUtil

用途：

- 文件系统常用操作封装。

核心接口：

- ListAllFile：递归列举后缀匹配文件。
- Mkdir：递归创建目录。
- IsRunningPidfile：检查 PID 文件对应进程状态。
- Rm/Mv/Unlink：删除、移动、取消链接。
- Realpath：解析规范路径。
- Symlink：创建符号链接。
- Dirname/Basename：路径切分。
- OpenForRead/OpenForWrite：读写文件流打开。

平台差异：

- IsRunningPidfile：
  - Linux：kill(pid, 0) 检查进程存在。
  - Windows：降级返回 false（不依赖系统 API）。

## Endian 模块

用途：

- 提供统一的字节序交换与主机字节序适配能力，服务于网络协议与二进制序列化场景。

核心常量：

- GYANIS_LITTLE_ENDIAN：小端常量（值 1）。
- GYANIS_BIG_ENDIAN：大端常量（值 2）。
- GYANIS_BYTE_ORDER：当前平台字节序常量。

核心接口：

- byteswap(value)：对 2/4/8 字节整型执行字节序交换。
- byteswapOnLittleEndian(value)：仅在小端平台交换字节序。
- byteswapOnBigEndian(value)：仅在大端平台交换字节序。

类型约束：

- 仅支持 2/4/8 字节整型。
- 使用 C++20 模板约束限制非法类型。

平台差异：

- 字节序判断优先使用 C++20 的 std::endian。
- Windows 使用 MSVC 内建字节交换函数。
- Ubuntu（GCC/Clang）使用编译器内建字节交换函数。
- 在缺失内建函数的环境下回退到位运算实现，确保可编译。

兼容性说明：

- 保持历史接口名不变，兼容既有调用点。
- 保持 GYANIS_BYTE_ORDER 常量语义不变。

## 最小示例

```cpp
#include "base/Config.h"
#include "base/Endian.h"
#include "base/Utils.h"

auto timeout = Gyanis::base::Config::LookUp<int>("server.timeout", 3000, "超时时间(ms)");
if (timeout)
{
    timeout->fromString("5000");
}

const auto encoded = Gyanis::base::StringUtil::UrlEncode("a/b c", true);
const auto decoded = Gyanis::base::StringUtil::UrlDecode(encoded, true);

auto tid = Gyanis::base::GetThreadID();
auto stack = Gyanis::base::backtraceToString(16, 1, "  ");

const auto network_port = Gyanis::base::byteswapOnLittleEndian<uint16_t>(8080);
```
